# LifeFlow v0.1

## 1. О проекте

LifeFlow — сервис для адаптивного планирования задач, который помогает пользователю не только создавать планы, но и перестраивать их при изменении обстоятельств.

Проект ориентирован на работу с долгосрочными задачами и призван помочь пользователю сохранить контроль над своими проектами даже в случае изменения первоначального плана.

---

## 2. Vision

LifeFlow помогает человеку не просто планировать задачи, а адаптировать планы под изменяющуюся реальность. Вместо накопления просроченных задач приложение помогает безопасно перестроить план, сохранив долгосрочные цели и снизив ощущение перегрузки.

---

## 3. Problem Statement

Современные планировщики задач хорошо помогают создавать и хранить планы, но плохо справляются с изменениями реальной жизни. При пропуске задач пользователь чаще всего получает лишь уведомление о просрочке или возможность перенести дедлайн вручную. По мере накопления просроченных задач план перестаёт отражать реальное положение дел и становится всё менее полезным.

Особенно это заметно при работе с долгосрочными проектами, обучением и задачами, рассчитанными на недели или месяцы. Изменение обстоятельств требует не просто переноса даты, а перестройки плана с учётом уже выполненной работы, текущей нагрузки и новых условий.

LifeFlow создаётся для решения этой проблемы: не просто хранить список задач, а помогать пользователю адаптировать план при изменении обстоятельств, сохраняя контроль над долгосрочными целями.

---

## 4. Target Audience

LifeFlow предназначен для людей, которые одновременно ведут несколько долгосрочных проектов и хотят не просто фиксировать задачи, а гибко управлять своим временем и адаптировать планы при изменении обстоятельств.

В первую очередь продукт ориентирован на:

- студентов;
- специалистов, одновременно работающих над несколькими проектами.

---

## 5. MVP (Starter)

Первая версия LifeFlow должна демонстрировать основную концепцию продукта: организацию долгосрочных проектов и ежедневную работу с задачами.

### Управление проектами

- Создание проекта;
- Редактирование проекта;
- Удаление проекта;
- Выбор категории проекта:
  - 📚 Учёба
  - 💼 Работа
  - 🏠 Личное
  - ✨ Другое

### Управление задачами

- Создание задачи;
- Редактирование задачи;
- Удаление задачи;
- Отметка задачи как выполненной.

### Структура задачи

Каждая задача должна содержать:

- название;
- описание;
- список подэтапов;
- дедлайн.

### Главный экран

Главным экраном приложения является раздел **«Мой день»**.

Он отображает:

- задачи, запланированные на текущий день;
- группировку задач по категориям проектов;
- экран завершения дня, если все задачи выполнены.

После выполнения всех задач пользователю предлагается:

- создать новую задачу;
- или перейти к просмотру задач следующего дня.

### Навигация

Первая версия приложения должна содержать следующие основные экраны:

- «Мой день»;
- список проектов;
- экран проекта;
- экран задачи.

## 6. User Journey

### Первый запуск

При первом запуске пользователь попадает не на экран «Мой день», а на экран создания первого проекта.

После создания первого проекта и первой задачи приложение переходит в обычный режим работы, где главным экраном становится «Мой день».

### Главный экран

Главный экран является рабочим пространством пользователя и отображает задачи, запланированные на текущий день, независимо от того, к какому проекту они относятся.

Если задачи на сегодняшний день отсутствуют, приложение предлагает пользователю:

- ➕ Добавить новую задачу;
- 📅 Посмотреть задачи на завтра.

---

## 7. Domain Model

### Проект

Проект объединяет задачи, относящиеся к одной долгосрочной цели пользователя.

Проект может существовать без задач. Это нужно для ситуаций, когда пользователь сначала фиксирует идею или направление работы, а задачи добавляет позже.

### Задача

Задача может существовать как внутри проекта, так и отдельно от него.

Это позволяет использовать LifeFlow как для долгосрочных проектов, так и для небольших повседневных дел, не требующих создания отдельного проекта.

Отдельная задача используется для простых личных дел, которые не относятся к долгосрочной цели. При необходимости пользователь может позже привязать отдельную задачу к существующему проекту.

При отметке задачи как выполненной она:

- получает статус "Выполнено";
- отображается в свернутом разделе "Выполнено";
- при необходимости пользователь может снова сделать её активной;

По умолчанию выполненные задачи отображаются отдельно от активных и не мешают работе с текущими задачами.

### Подэтап

Подэтап — небольшой шаг внутри задачи, который помогает разбить задачу на управляемые части.

Подэтап всегда принадлежит задаче и не существует отдельно от неё.

Описание подэтапа нужно для дополнительного контекста: заметок, ссылок, уточнений, вопросов или инструкций.

В будущем подэтап может быть расширен дополнительными метаданными, необходимыми для автоматизации отдельных сценариев работы, например поиска вакансий, хранения ссылок или выполнения регулярных запросов. Это позволит использовать LifeFlow не только как планировщик, но и как инструмент автоматизации повторяющихся действий, например поиска вакансий.

### Внутренние уведомления

В Starter LifeFlow может показывать внутренние уведомления при открытии приложения.

Уведомления используются для того, чтобы обратить внимание пользователя на важные изменения:
- подошёл дедлайн задачи;
- есть просроченные задачи;
- есть задачи, требующие проверки.

На первом этапе уведомления не являются push-уведомлениями и работают только внутри приложения.

В будущем механизм внутренних уведомлений может использоваться для автоматизированных действий, например для результатов парсера вакансий или других регулярных проверок.

## 8. Functional Requirements

### 8.1 Проекты

- Пользователь может просмотреть список всех проектов.
- Пользователь может создать проект.
- Пользователь может отредактировать проект.
- Пользователь может удалить проект.
- Пользователь может выбрать категорию проекта: Учёба, Работа, Личное, Другое.
- Пользователь может открыть проект и увидеть связанные с ним задачи.

### 8.2 Задачи

- Пользователь может создать задачу.
- Пользователь может создать задачу внутри проекта.
- Пользователь может создать отдельную задачу без проекта.
- Пользователь может отредактировать задачу.
- Пользователь может удалить задачу.
- Пользователь может отметить задачу как выполненную.
- Пользователь может вернуть выполненную задачу в активные.

### 8.3 Подэтапы

- Пользователь может добавить подэтап к задаче.
- Пользователь может отредактировать подэтап.
- Пользователь может удалить подэтап.
- Пользователь может отметить подэтап как выполненный.

### 8.4 Мой день

- Пользователь может открыть экран «Мой день».
- Экран «Мой день» показывает задачи, запланированные на текущий день.
- Задачи на экране «Мой день» группируются по категориям проектов.
- Если все задачи выполнены, приложение показывает сообщение о завершении дня.
- После выполнения всех задач приложение предлагает добавить новую задачу или посмотреть задачи на завтра.

### 8.5 Внутренние уведомления

- Приложение может показывать внутренние уведомления при открытии.
- Приложение может сообщать о приближении дедлайна.
- Приложение может сообщать о просроченных задачах.
- Приложение может сообщать о задачах, требующих проверки.

---

## 9. Non-functional Requirements

### Адаптивность интерфейса

На этапе Starter LifeFlow разрабатывается как веб-приложение.

Интерфейс должен быть адаптирован для использования как на компьютере, так и на мобильных устройствах через браузер.

Приложение должно корректно отображаться на разных размерах экрана и сохранять базовые сценарии работы:

- просмотр задач текущего дня;
- создание и редактирование проектов;
- создание и редактирование задач;
- работа с подэтапами.

---

## 10. Roadmap

Развитие LifeFlow разделено на три этапа. Такой подход позволяет сосредоточиться на создании стабильного MVP, а затем постепенно расширять функциональность без необходимости переработки архитектуры.

### Starter

Первая версия продукта, реализуемая в рамках хакатона.

Функциональность:

- управление проектами;
- управление задачами;
- управление отдельными задачами;
- управление подэтапами;
- категории проектов;
- экран «Мой день»;
- внутренние уведомления;
- отображение выполненных задач;
- базовая навигация по приложению.

Цель этапа — создать полностью работоспособную систему управления проектами и задачами.

---

### Advanced

Функции, расширяющие возможности планирования.

Планируется реализовать:

- объединение просроченной задачи с задачей текущего дня;
- перенос дедлайнов;
- выбор дней выполнения повторяющихся задач;
- расширенные фильтры;
- поиск;
- улучшенная работа со списками;
- синхронизация проектов между устройствами.

Цель этапа — сделать работу с долгосрочными проектами более удобной и гибкой.

---

### Future

Долгосрочное развитие продукта.

Планируется исследовать и реализовать:

- интеграцию с Google Calendar;
- интеграцию с календарём устройства;
- push-уведомления;
- автоматическую адаптацию планов;
- систему анализа нагрузки пользователя;
- инструменты автоматизации (парсеры, регулярные проверки, работа с внешними сервисами);
- интеллектуальные рекомендации по планированию.

Цель этапа — превратить LifeFlow из планировщика задач в персональную систему управления долгосрочными проектами.
